## 0. 给 Codex 的执行说明

请先完整阅读本规范和随附的高保真原型图，再开始实现。原型图用于确定视觉方向；本文用于约束真实交互、编辑器行为、工程边界和验收标准。不要只复刻静态截图，也不要为了快速实现而牺牲编辑体验。

实施前先检查现有项目结构、依赖和已有功能，在尽量保留可用代码的前提下迭代。不要未经确认重建项目或替换已经确定的技术栈。

-   技术基线：Electron + Vue 3 + TypeScript + Vite + Pinia + Tiptap /
    ProseMirror。
-   目标平台：Windows 与 macOS 桌面端。
-   编辑器是产品核心能力，输入、选区、中文输入法、撤销重做、粘贴和自动保存的可靠性优先于装饰效果。
-   不要把业务逻辑塞进 Tiptap 扩展，也不要把 Electron 主进程当作业务层。
-   完成每个阶段后运行类型检查、测试和构建；修复问题后再进入下一阶段。

## 2. 页面总体布局

### 2.1 三栏结构

  ----------------------------------------------------------------------------------------------------------
  区域                    职责                                 行为要求
  ----------------------- ------------------------------------ ---------------------------------------------
  左侧主导航              首页、知识库、日志、AI 助手、设置    支持收窄为图标栏；当前模块状态清晰

  中间资源栏              文档树、分类、搜索、最近编辑         支持折叠/隐藏、调整宽度；树节点展开状态稳定

  右侧编辑区              文档信息、格式工具栏、正文、状态栏   占据主要空间；正文宽度可调；支持专注模式
  ----------------------------------------------------------------------------------------------------------

-   三栏宽度可拖动调整，提供合理最小宽度，避免编辑区被挤压。
-   中间资源栏和左侧导航均可隐藏；专注模式下隐藏非必要侧栏。
-   编辑区顶部的文档标题、标签、分享等文档级操作，与正文格式工具栏分层。
-   工具栏固定在编辑区顶部；正文独立滚动，不能产生页面级横向滚动条。
-   适配 Windows 与 macOS
    窗口控制区域，避免自绘标题栏控件与系统按钮重叠。

### 2.2 文档头部

-   显示面包屑路径、文档图标、文档标题、标签、最后编辑时间。
-   支持重命名、收藏/重要标记、分享。若当前版本尚未实现分享，则隐藏或标记为未启用，不做假按钮。
-   自动保存状态应清楚但低干扰，例如"正在保存... / 已保存 / 保存失败"。
-   文档标题区与正文之间留出明确层级，但不能占用过多垂直空间。

## 3. 编辑器核心交互规范

### 3.1 顶部格式工具栏

工具栏采用单行、固定、紧凑布局。常用功能直接可见，低频功能收纳到"更多"菜单。任何窗口尺寸下都不允许出现横向滚动条；空间不足时应按优先级折叠按钮或进入更多菜单。

  分组       功能
  ---------- --------------------------------------------------------
  块类型     正文、标题 1、标题 2、标题 3（可按产品需要增加标题 4）
  文字格式   粗体、斜体、下划线、删除线、行内代码
  颜色       文字颜色、背景高亮
  插入       链接、图片、附件、表格
  块元素     引用、无序列表、有序列表、任务列表、代码块、分割线
  编辑操作   撤销、重做
  更多       对齐、缩进、清除格式及其他低频操作

-   按钮有默认、悬停、按下、激活、禁用状态；图标风格、尺寸、间距统一。
-   工具栏按钮必须有 tooltip，显示功能名称和快捷键（如有）。
-   工具栏点击后不能意外丢失当前选区；格式操作应作用于触发前的编辑器选区。
-   工具栏不应把所有功能挤在一行；应设置优先级和折叠规则。

### 3.2 正文画布与排版

  属性           建议默认值/规则
  -------------- ---------------------------------------------
  正文最大宽度   约 820px；可提供舒适宽度与宽屏模式
  正文字号       16px（允许用户调整）
  正文行高       约 1.75；避免过松或过紧
  段落间距       约 0.65em--0.85em；连续回车不得产生夸张空白
  标题           建立明确字号、字重、上下间距层级
  页面底色       柔和浅色；正文画布保持干净、低干扰
  选区           轻柔紫色半透明高亮，不添加厚重阴影
  链接           颜色和 hover 状态清楚，支持打开/编辑
  图片/表格      不溢出正文宽度；支持选中、调整和删除

特别要求：必须显式定义编辑器内部
`p`、`h1-h6`、`ul`、`ol`、`li`、`blockquote`、`pre`、`table`、`img`
等元素的 margin、padding、line-height、font-size 和
box-sizing。不能依赖浏览器默认样式，也不能让全局 UI CSS
意外覆盖编辑器样式。

按 Enter
创建新段落时，段落间距应稳定且适中；连续输入、换行、列表续项、列表退出、标题后回车等行为均需测试。

### 3.3 Markdown 输入规则

-   支持常见 Markdown 快捷输入：`#` 生成标题、`-` 或 `*`
    生成无序列表、`1.` 生成有序列表、`>` 生成引用、\`\``触发代码块、`\[
    \]\` 触发任务项（具体规则按扩展实现验证）。
-   支持 `**粗体**`、`*斜体*`、`` `行内代码` `` 等常见输入规则。
-   Markdown 快捷输入应可预测，不得在中文输入法组合输入过程中误触发。
-   底层规范数据仍为 Tiptap JSON；Markdown
    用于输入、导入、导出和交换，不作为第二个独立主数据源。
-   复杂自定义模块需要定义 Markdown
    导出策略：可无损导出则正常导出；不能无损表达时给出明确降级方案，不静默丢失内容。

### 3.4 Slash 插入菜单

在空段落或合适的块级位置输入 `/`
时，唤起插入菜单。菜单锚定当前光标附近，随滚动、窗口缩放和选区变化重新定位。不能覆盖正在输入的文字；靠近视口边缘时自动调整弹出方向。

  ----------------------------------------------------------------------------------------------------------------
  分类                                首批项目
  ----------------------------------- ----------------------------------------------------------------------------
  基础内容                            正文、标题、引用、代码块、分割线

  列表                                无序列表、有序列表、任务清单

  媒体                                图片、附件、链接

  表格                                表格

  拾知结构化模块                      问题记录、解决方案、任务清单、信息卡片、学习笔记、思维导图（可分阶段实现）
  ----------------------------------------------------------------------------------------------------------------

-   支持键盘上下选择、Enter 确认、Esc 关闭、输入关键词过滤。
-   菜单关闭后光标落在合理位置，不能丢失焦点或产生额外空段落。
-   结构化模块按需插入，不应让普通文档被迫使用卡片式编辑。

### 3.5 选区浮动工具栏（Bubble Menu）

-   仅在存在有效文本选区时显示；无选区时隐藏。
-   位置根据选区实时计算，避免超出窗口边界。
-   首批操作：粗体、斜体、下划线、文字颜色、背景高亮、链接、更多。
-   选区背景采用轻柔紫色，不使用大面积阴影或模糊遮罩。
-   鼠标点击浮动工具栏时保留编辑器选区；操作完成后焦点和选区行为符合预期。
-   中文输入法 composition 状态下不要因选区变化频繁闪烁菜单。

### 3.6 图片、表格、代码与粘贴

-   图片支持插入、删除、合理缩放、对齐和替代文本；图片文件保存到应用附件目录，文档中存储稳定引用，不写入机器绝对路径。
-   表格支持行列增删、单元格编辑、基本对齐；表格不能破坏正文滚动和布局。
-   代码块支持语言标记、等宽字体和横向溢出处理；代码块内部快捷键行为合理。
-   粘贴网页/Word
    内容时清理无关字体、颜色、复杂嵌套样式，尽量保留标题、列表、链接、图片和表格等语义结构。
-   剪贴板同时处理纯文本与 HTML 内容；不能把整页网站 CSS 原样带入文档。

## 4. 萌宠与视觉规范

-   萌宠属于应用外壳，不属于编辑器正文；默认放在导航栏底部或独立陪伴区域。
-   编辑区默认不悬浮显示宠物，不允许遮挡文字、光标、选区、工具栏和插入菜单。
-   支持隐藏萌宠；专注模式默认隐藏或弱化萌宠。
-   动画只在保存完成、完成记录等低频时机轻量反馈，不持续循环干扰。
-   首页可以更活泼；知识库与编辑页应克制，保持长时间阅读舒适。

  设计项   建议
  -------- --------------------------------------------------------
  主色     柔和紫色作为品牌强调色
  主题     浅色默认，深色可切换；后续可扩展薄荷绿、奶油黄、樱花粉
  圆角     统一使用小/中/大三级圆角，不要所有区域都做成厚重卡片
  阴影     轻量、低对比；编辑正文区域尽量无明显投影
  图标     统一线性图标体系，保持尺寸和笔画一致
  动效     短、轻、可预测；尊重系统减少动态效果设置

## 5. 编辑器状态与行为

  状态        预期行为
  ----------- ----------------------------------------------------
  空白文档    显示轻量占位提示；点击即可输入，不出现复杂引导卡片
  正常输入    光标稳定；输入、回车、删除、方向键行为自然
  选中文字    选区清楚；按需出现 Bubble Menu
  输入 `/`    出现 Slash Menu；支持键盘导航与过滤
  保存中      状态栏/文档头部轻量提示；输入不中断
  保存失败    明确提示并允许重试；不得静默丢弃编辑内容
  专注模式    隐藏侧栏和非必要元素，保留正文与必要操作
  只读/预览   禁止误编辑；视觉上明确区分编辑与只读状态
  窗口缩放    工具栏重排/折叠，浮层重新定位，正文不横向溢出

## 6. 自动保存、撤销历史与数据可靠性

-   采用防抖自动保存，但保存调度不能阻塞输入；建议先在编辑器状态层收集变更，再由文档服务持久化。
-   保存应具备失败反馈、重试机制和未保存状态提示。
-   保存成功不能重建 Editor 实例，不能重置光标、选区或撤销历史。
-   撤销/重做应使用 ProseMirror 事务历史；不要通过重新加载整篇 JSON
    实现撤销。
-   文档 JSON 是规范内容；附件通过稳定 ID/相对资源引用关联。
-   为未来版本快照和同步预留 `revision` / `version` / `updatedAt` /
    `deletedAt` 等元数据，但当前不实现云同步。

## 8. CSS 与布局防回归约束

-   编辑器样式必须有独立命名空间，例如 `.shizhi-editor`；避免全局
    `p`、`h1`、`button` 等选择器污染编辑器。
-   明确设置 `box-sizing: border-box`；统一定义正文排版 token。
-   编辑器内容区的 `p`、`li`、`blockquote`、`pre`、`table`
    等样式必须显式定义。
-   工具栏使用 flex 布局并设置 `flex-shrink` / overflow 策略，不能靠
    `overflow-x:auto` 解决空间问题。
-   浮动菜单使用统一定位方案，处理滚动容器、窗口边缘和缩放；不要用固定像素猜测位置。
-   检查 z-index 层级，确保菜单不会被侧栏、正文或窗口装饰裁切。
-   颜色必须使用主题变量，切换深色主题时正文、选区、菜单、边框、placeholder
    均正确适配。
-   不要使用 `!important` 堆叠修复；优先修正样式作用域和组件层级。

## 11. 原型图使用说明

随附原型图是本规范的重要组成部分。请 Codex
重点参考：三栏层级、文档头部、工具栏位置、正文留白、柔和紫色主题和萌宠在应用外壳中的位置。

原型图中的右侧"常用块/结构化模块"浮动面板仅用于展示可插入模块的能力，不应在编辑器默认状态下长期悬浮覆盖正文。实际产品应改为按需唤起的
Slash Menu 或插入面板。

## 12. 完成定义

文档编辑页只有在以下条件同时满足时才视为完成：

-   视觉结构与原型方向一致，布局清晰、正文突出。
-   核心编辑交互可用，中文输入、回车排版、选区、浮层、粘贴和撤销重做可靠。
-   保存和重新打开数据正确，不丢内容、不破坏编辑状态。
-   工具栏没有横向滚动条，浮动组件不遮挡文字或光标。
-   Windows 与 macOS 均完成基本验证。
-   验收清单逐项测试，未完成项明确记录，不以"页面能打开"作为完成标准。
